# 1.0.0

Initial release. Replaces `jiwer` for this repo's use.

- `calculate_wer(reference, hypothesis)`: Word Error Rate via standard
  Levenshtein distance (S+D+I edit count) / reference word count.
- `calculate_cer(reference, hypothesis)`: Character Error Rate, same
  algorithm, character sequence instead of word sequence (whitespace
  counts as a character).
- Both accept a single string pair, or equal-length lists of strings for
  batch scoring. Batch mode pools edit distance and unit count across
  every pair before dividing once (the correct way to compute a
  corpus-level rate), not the average of each pair's individual rate.
- Both raise `ValueError` on an empty reference (nothing to divide by)
  or mismatched batch lengths.
- `split_repeated_words` param on both: fixes word-level WER/CER
  blowing up on a glued-repetition spacing artifact (e.g. some SADA
  transcripts write `"لالالالا"` where the hypothesis says
  `"لا لا لا لا"`, same content, scored as 4 errors). Defaults to
  `DEFAULT_SPLIT_REPEATED_WORDS` (`["لا"]`), corpus-verified against
  ~150k real transcript lines, every other short Arabic
  particle/interjection tested (`يا`, `ها`, `وا`, `ما`) either had no
  glued evidence, too-thin/ambiguous evidence, or collided with a real
  lexicalized word (`ما` is almost always `ماما`, "mom"), see the
  constant's comment in `metrics.py` for the per-word reasoning. Pass
  `[]` to disable, or your own list to replace the default (not merged
  with it). Only a token that's *entirely* a listed word repeated 2+
  times gets split, never a substring, so it can't touch a real word
  that merely has the same repeated-pair shape (`مهمه`, `امام`).
- Validated against real data: reproduced the published `results.json`
  WER/CER for 3 of 4 benchmark datasets (common_voice, mgb-2, casablanca)
  within ~1 point after normalizing with `asr_utils.normalization`. The
  4th (masc) diverged by ~9 points; ruled out a bug in this package via
  hand-worked test cases, the algorithm's known correctness, and a
  `difflib` cross-check on 2000 real samples, the cause is external
  (likely a stale `results.json` or different upstream reference source).
