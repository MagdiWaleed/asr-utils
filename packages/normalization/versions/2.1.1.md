# 2.1.1

Changed from 2.1.0. All fixes, no API/signature changes.

- Fixed: `eot_token`-only hypotheses (`<eot>`, `. <eot>`) collapsed to `""`
  instead of staying `<eot>`. Found by running the full real benchmark
  corpus (115k lines) through `normalize_text`. "Nothing said, just
  end-of-turn" was being erased to indistinguishable-from-empty.
- Fixed a batch of `normalize_numbers` bugs found via the same real-corpus
  sweep plus a recorded set of normalization issues:
  - Chained multipliers now multiply instead of sum (`مائة ألف` → 100000,
    was 1100), including 3-term chains (`خمسة مائة الف` → 500000).
  - `و` glued to the next number word with no space (`وعشرين`) is now
    split off before matching, was structurally invisible to the parser.
  - Dual-inflected numbers added: `الفين`/`ألفين` (2000), `مئتين`/`ميتين`/
    `مائتين` (200).
  - Million/billion added to the multiplier map.
  - Colloquial hundred spellings `مية`/`ميه`/`مئه` added (`مئة`/`مائة`
    already existed but `مئه` was also missing).
  - Dialect fused teens (`خمس طعش` → 15, `ثلاث طعشر` → 13).
  - Tanwin-carrier alif on number words (`ثلاثاً` → matches `ثلاث`); the
    doc's own `أربعاً` example additionally needs `أ→ا` hamza folding,
    which stays removed (deliberate, matches production training code).
  - Glued hundred-compounds (`ثلاثمائة` → 300, `ستمائة` → 600, one fused
    word) — 203 real occurrences, not in the original punch list.
  - `مائة` (hamza+ة spelling) and `مئه` (hamza+ه, no alif) were both
    missing from the multiplier map entirely; the punch list's own repro
    commands relied on `مائة` without it actually being present.

**Known remaining gap, documented not fixed:** a glued hundred-compound
followed by `و` + tens + a multiplier (`ثلاثمائة وخمسين ألف`, want 350000)
computes 50300 — the tens gets multiplied alone instead of combined with
the hundred first. A linear single-pass parser can't resolve this without
breaking `ميتين و سبع مية` (900, correctly handled), which needs the
opposite treatment of the same connector. ~8 occurrences across the full
115k-line corpus. Needs real lookahead to fix properly.

**Explicitly out of scope:** fraction/half words (`نص`, `ربع`) — needs a
product decision on whether they should become digits at all, not a code
fix. Idiomatic repeated-multiplier false positive (`الف الف الف` as a
blessing phrase, not literal 3000) — rare, not worth guarding against yet.
