# 2.1.0

Changed from 2.0.0:

- **Behavior change for existing callers, no new args needed:** any
  `<...>` tag span (brackets and contents, e.g. `<afdaslk>`, `<noise>`)
  is now stripped entirely. Previously only the brackets were dropped by
  the punctuation filter and the inner letters survived as plain text
  (`<afdaslk>` to `afdaslk`); now the whole span is removed.
- **Behavior change:** `eot_token` now defaults to `"<eot>"` even when
  not passed. A literal `<eot>` in the input is protected from the tag
  stripping above and given the usual eot spacing/leading-strip
  treatment, where previously (no `eot_token` given) it would have been
  stripped like any other tag.
- Added `include_folding` / `exclude_folding` params to `normalize_text`:
  control which hamza-variant characters get folded to `ا` (currently
  only `آ` is reachable through the fold step, the others are already
  stripped upstream by `URDU_CHARS_PATTERN`).
- Added `enable_special_tokens` param: extra `<...>` tokens to keep
  intact alongside the eot marker, e.g. `enable_special_tokens=["<noise>"]`.
  Unlike `eot_token`, these get no leading-strip treatment.
- Added docstrings to `normalize_text` and `normalize_numbers` covering
  every parameter.
