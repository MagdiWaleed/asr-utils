# 3.2.0

Changed from 3.1.0:

No signature-breaking or import-path change, and **no change to default
output**: both new parameters default to the 3.1.0 behavior, verified by
normalizing all 393,334 reference and hypothesis strings in
`an evaluation corpus/output/*.jsonl` under 3.1.0 and 3.2.0 and diffing (0
differences). WER/CER scored with 3.1.0 stays directly comparable unless
you opt into a flag below.

`normalize_text`, new parameters
- `keep_percent=False`. When `True`, a `%` that belongs to a number is kept
  and glued to it, always in the same order: `"100% من"` -> `"100% من"`,
  `"٪٥٠"` -> `"50%"`, `"%50"` -> `"50%"`, `"50 %"` -> `"50%"`,
  `"% 50"` -> `"50%"`. The sign binds to the side it already touches
  without a space, so two numbers stay two numbers
  (`"عام 2020 %50"` -> `"عام 2020 50%"`, not `"2020%50"`). A `%` not bound
  to a number is still stripped (`"% alone"` -> `"alone"`).
- `keep_time_colon=False`. When `True`, a `:` between digits is kept like a
  decimal point: `"6:00"` -> `"6:00"`, `"2:1"` -> `"2:1"`,
  `"6:00:30"` -> `"6:00:30"`. A colon outside digits is still stripped
  (`"قال: نعم"` -> `"قال نعم"`).

Default is off for both because an ASR model says the words
("في المية", "percent") rather than emitting the symbol — 0 of the 196,667
hypothesis lines in `an evaluation corpus/output` contain a `%`. Keeping it in a
reference therefore costs a substitution plus insertions: on
`"100% من خدماته"` against a spoken `"مية في المية من خدماته"`, WER is 0.67
with the symbol stripped and 1.00 with it kept. Turn the flags on for
training labels that keep written symbols, not for scoring.

Fixed, output changes only for callers already passing these
- `enable_punc=[":"]` no longer inserts a space inside a clock time:
  `"الساعة 6:00"` -> `"الساعة 6:00"` (was `"الساعة 6: 00"`, a different
  reading). `:` now joins `.` and `,` in the tight-spacing rule.
- The Arabic percent sign `٪` (U+066A) folds to `%` before the
  Urdu/extended-Arabic strip that used to delete it, so one spelling
  reaches every later step and `enable_punc=["%"]` matches the Arabic
  spelling too: `"٥٠٪"` with `enable_punc=["%"]` -> `"50%"` (was `"50"`),
  with `enable_punc=["٪"]` -> `"50%"` (was `"50٪"`). With neither, `٪` is
  stripped exactly as before.

Tests: 5 new tests in `test_normalization.py` (default unchanged,
`keep_percent`, `keep_time_colon`, `enable_punc` interactions, idempotency
across flag combinations), 52 passing. `example.py`/`example.md` gain a
percent/clock-time section and the two new parameters in the signature.
