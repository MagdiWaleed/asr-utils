# 3.0.0

Changed from 2.2.3:

- **BREAKING:** `eot_token` default behavior reversed. Previously
  `eot_token=None` still protected a literal `"<eot>"` from the tag
  stripper. Now it protects nothing, `"<eot>"` is treated as any other
  `"<...>"` tag and gets stripped entirely.
  ```python
  # before (2.2.3 and earlier)
  normalize_text("hello <eot> world")
  # -> 'hello <eot> world'
  # now
  normalize_text("hello <eot> world")
  # -> 'hello world'
  ```
  Existing callers relying on the implicit `"<eot>"` default must now
  pass `eot_token="<eot>"` explicitly to keep the old behavior. Any
  string works as the marker, not just `"<eot>"`, e.g.
  `eot_token="<endofturn>"` or `eot_token="<end-of-turn>"`. Only the
  exact token passed is protected, a literal `"<eot>"` elsewhere in the
  text is no longer special once a different `eot_token` is active.
- Fixed: `normalize_numbers("<eot>", eot_token="<eot>")`-style leading-
  eot-alone-is-kept behavior (added in 2.1.1) is unchanged, it just now
  only applies when `eot_token` is actually given, matching the rest of
  this release.
- Updated `example.py`/`example.md` to reflect the new default.

Full test suite (37 tests) and the 230,546-field, 115k-line real
benchmark corpus sweep both pass clean, 0 crashes. The corpus sweep's
"collapsed to empty" count rose from 6 to 45, expected: every eot-only
hypothesis (`"<eot>"` alone) with no `eot_token` passed now correctly
collapses to `""` instead of being silently kept.
